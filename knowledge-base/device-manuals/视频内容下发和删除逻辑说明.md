# 视频内容下发和删除逻辑说明

## 一、系统架构

### 1.1 核心组件

| 组件 | 类名 | 职责 |
|------|------|------|
| 消息监听器 | `PlaybackConfigDispatchWebSocketMessageListener` | 接收WebSocket消息，参数校验，异步处理 |
| 媒体文件服务 | `MediaFileService` | 文件下载、MD5校验、文件移动、配置管理 |
| 配置文件服务 | `MediaConfigFileService` | 管理进度条配置和营销活动配置 |
| 媒体客户端 | `MediaClient` | 通知设备配置更新 |

### 1.2 消息流转

```
Server (WebSocket)
    ↓
PlaybackConfigDispatchWebSocketMessageListener (异步处理)
    ↓
MediaFileService (业务逻辑)
    ↓
MediaConfigFileService (配置持久化)
    ↓
MediaClient (通知设备)
    ↓
ACK Response (返回处理结果)
```

## 二、操作类型

### 2.1 operationType（操作类型）

| 值 | 操作 | 说明 |
|----|------|------|
| 1 | 下发 | 下载媒体文件并保存配置 |
| 2 | 删除 | 删除媒体文件和配置 |
| 3 | 修改 | 仅更新配置文件，不下载文件 |

### 2.2 configType（配置类型）

| 值 | 类型 | 文件命名规则 | 存储路径 |
|----|------|-------------|---------|
| 1 | 设备待机视频 | `standby_video.mp4` / `standby_audio.mp3` | `/data/default/` |
| 2 | 饮品制作视频 | `{businessCode}.mp4` / `{businessCode}.mp3` | `/data/drink/video/` 或 `/data/drink/audio/` |
| 3 | 营销活动视频 | `activity_{configId}.mp4` / `activity_{configId}.mp3` | `/data/drink/video/` 或 `/data/drink/audio/` |

### 2.3 businessType（业务类型）

| 值 | 类型 | 说明 |
|----|------|------|
| 1 | 通用 | 设备待机视频等通用配置 |
| 2 | 餐品 | 与具体餐品关联的视频配置 |

## 三、下发流程（operationType=1）

### 3.1 流程图

```
接收WebSocket消息
    ↓
参数校验（reqId、operationType、configId、mediaList等）
    ↓
遍历媒体列表 (mediaList)
    ↓
┌─────────────────────────────────────┐
│ 处理单个媒体文件 (processSingleMedia) │
└─────────────────────────────────────┘
    ↓
确定目标文件路径（根据configType）
    ↓
检查目标文件MD5 ◄─────────┐
    ↓                      │
MD5匹配？                  │
    ├─ 是 → 跳过下载，返回成功
    └─ 否 ↓
下载到临时文件夹 (/temp)
    ↓
验证下载文件MD5
    ↓
MD5验证通过？
    ├─ 否 → 删除临时文件，返回失败
    └─ 是 ↓
移动到待转移文件夹 (/pending) [覆盖已存在文件]
    ↓
保存配置文件
    ↓
移动待转移文件到目标位置 (/data) [覆盖已存在文件]
    ↓
清空临时文件夹
    ↓
发送ACK响应
```

### 3.2 关键特性

#### 3.2.1 MD5校验机制
- **下载前检查**：如果目标文件已存在且MD5匹配，跳过下载
- **下载后验证**：验证下载文件MD5，不匹配则删除并返回失败
- **作用**：避免重复下载，节省带宽和时间，保证幂等性

#### 3.2.2 三级文件夹机制
```
/temp (临时下载)
    ↓
/pending (待转移)
    ↓
/data (最终目标)
```

**设计目的：**
- `temp`：下载过程中的临时存储，下载失败可直接删除
- `pending`：下载完成但未部署的文件，程序崩溃后可恢复
- `data`：最终的媒体文件存储位置

#### 3.2.3 文件覆盖策略
- 移动到 `pending` 时：使用 `StandardCopyOption.REPLACE_EXISTING`
- 移动到 `data` 时：使用 `StandardCopyOption.REPLACE_EXISTING`
- **结果**：新文件会覆盖旧文件，确保内容更新

#### 3.2.4 下载超时控制
- 连接超时：15秒
- 读取超时：60秒
- 下载进度日志：
  - 已知大小：每10%打印一次
  - 未知大小：每5MB打印一次

### 3.3 文件已存在的处理

| 场景 | MD5状态 | 处理方式 |
|------|---------|---------|
| 目标文件已存在 | MD5匹配 | ✅ 跳过下载，直接返回成功 |
| 目标文件已存在 | MD5不匹配 | ⚠️ 下载新文件，覆盖旧文件 |
| 目标文件不存在 | - | 📥 正常下载流程 |

### 3.4 配置文件保存

#### 3.4.1 饮品制作视频（configType=2）
- **配置文件**：`/home/smyze/config/machine/drink_progress_config.json`
- **内容格式**：
```json
{
  "businessCode1": 100,
  "businessCode2": 120,
  "businessCode3": 150
}
```
- **保存规则**：
  - `progressBarCreation != 0`：保存或更新配置
  - `progressBarCreation == 0`：删除配置

#### 3.4.2 营销活动视频（configType=3）
- **配置文件**：`/home/smyze/config/machine/activity_media_config.json`
- **内容格式**：
```json
[
  {
    "configId": 123,
    "mediaName": "activity_123",
    "startTime": "10:00:00",
    "endTime": "11:00:59"
  }
]
```
- **保存后操作**：调用 `MediaClient.notifyPlaybackConfigUpdate()` 通知设备

## 四、删除流程（operationType=2）

### 4.1 流程图

```
接收WebSocket消息
    ↓
参数校验
    ↓
遍历媒体列表
    ↓
根据configType确定目标文件路径
    ↓
删除物理文件
    ↓
删除配置文件
    ├─ configType=2 → 删除 drink_progress_config.json 中的对应项
    └─ configType=3 → 删除 activity_media_config.json 中的对应项
                      + 通知设备配置更新
    ↓
发送ACK响应
```

### 4.2 删除规则

| 配置类型 | 删除内容 | 额外操作 |
|---------|---------|---------|
| configType=1 | 删除待机视频文件 | 无 |
| configType=2 | 删除饮品视频文件 + 进度条配置 | 无 |
| configType=3 | 删除活动视频文件 + 活动配置 | 通知设备更新 |

### 4.3 容错处理
- 文件不存在时：记录日志，不报错，继续处理
- 配置删除失败：记录错误日志，不影响文件删除

## 五、修改流程（operationType=3）

### 5.1 流程图

```
接收WebSocket消息
    ↓
参数校验
    ↓
遍历媒体列表
    ↓
更新配置文件（不下载文件）
    ├─ configType=2 → 更新或删除进度条配置
    └─ configType=3 → 更新活动时间配置 + 通知设备
    ↓
发送ACK响应
```

### 5.2 修改规则

**特点**：只更新配置文件，不下载新的媒体文件

| 配置类型 | 修改内容 | 说明 |
|---------|---------|------|
| configType=2 | 更新 `progressBarCreation` | 值为0时删除配置 |
| configType=3 | 更新 `startTime` 和 `endTime` | 修改活动播放时间段 |

## 六、防重复处理机制

### 6.1 实现方式
```java
private final ConcurrentHashMap<String, Boolean> processingRequests = new ConcurrentHashMap<>();

// 防止重复处理相同请求
if (processingRequests.putIfAbsent(reqId, true) != null) {
    log.warn("请求 {} 正在处理中，跳过重复处理", reqId);
    return false;
}
```

### 6.2 作用
- 同一 `reqId` 不会被重复处理
- 避免并发请求导致的重复下载或删除
- 处理完成后自动从 Map 中移除

## 七、启动时恢复机制

### 7.1 启动流程
```java
@PostConstruct
public void init() {
    movePendingFilesOnStartup();
}
```

### 7.2 恢复逻辑
1. 检查 `/pending` 文件夹是否存在
2. 遍历 pending 文件夹中的所有文件
3. 根据文件名判断目标路径：
   - `standby_*.mp4` → `/data/default/standby_video.mp4`
   - `standby_*.mp3` → `/data/default/standby_audio.mp3`
   - `{businessCode}.mp4` → `/data/drink/video/{businessCode}.mp4`
   - `{businessCode}.mp3` → `/data/drink/audio/{businessCode}.mp3`
4. 移动文件到目标位置（覆盖已存在文件）
5. 清空 `/temp` 临时文件夹

### 7.3 设计目的
- 处理程序崩溃或重启时未完成的文件部署
- 确保已下载的文件最终能部署到目标位置
- 保证系统的容错性和一致性

## 九、异常处理

### 9.1 下载异常

| 异常类型 | 处理方式 |
|---------|---------|
| `FileNotFoundException` | 记录错误日志，删除临时文件，返回失败 |
| `SocketTimeoutException` | 记录超时日志，删除临时文件，返回失败 |
| `IOException` | 记录IO异常日志，删除临时文件，返回失败 |
| HTTP响应码非200 | 记录错误日志，返回失败 |
| MD5验证失败 | 删除临时文件，返回失败 |

### 9.2 参数校验

必填参数：
- `reqId`：请求唯一标识
- `operationType`：1、2或3
- `businessType`：1或2
- `configId`：配置ID
- `mediaList`：媒体列表（长度1-10）
- `mediaList[].mediaId`：媒体ID
- `mediaList[].mediaType`：1或2
- `mediaList[].mediaUrl`：下载地址
- `mediaList[].fileMd5`：文件MD5

条件必填：
- `businessType=2` 时，`businessCode` 必填
- `configType=3` 时，`activityStartTime` 和 `activityEndTime` 必填

## 十一、总结

### 11.1 设计优点
✅ **幂等性**：MD5校验避免重复下载
✅ **容错性**：三级文件夹机制 + 启动恢复
✅ **并发安全**：防重复处理机制
✅ **可追溯**：详细的日志记录
✅ **灵活性**：支持三种操作类型和三种配置类型

### 11.2 关键机制
- **MD5校验**：确保文件完整性和避免重复下载
- **文件覆盖**：确保内容更新时能正确替换旧文件
- **异步处理**：使用线程池处理消息，不阻塞WebSocket连接
- **ACK响应**：处理完成后返回结果，便于服务端追踪
- **配置通知**：营销活动配置变更后通知设备更新

### 11.3 适用场景
- 边缘设备的媒体内容分发
- 需要断点续传和容错恢复的文件下载
- 多种配置类型的统一管理
- 实时配置更新和通知
