# 版本同步逻辑说明

## 概述

版本同步由 `ReleaseSyncServiceImpl` 负责，应用启动后以定时任务方式运行，定期检查云端版本与本地版本是否一致，不一致则自动拉取新版本资源。

## 定时任务配置

```yaml
# application-prod.yml
smyze:
  release-sync:
    enabled: true          # 是否启用版本同步
    period-time: 1800      # 同步周期，单位：秒（默认30分钟）
```

## 同步前提条件

以下条件必须全部满足，否则不会触发同步：

| 序号 | 条件 | 代码位置 |
|------|------|----------|
| 1 | `release-sync.enabled = true` | ReleaseSyncServiceImpl:78 |
| 2 | 主机名 ≠ `F000` （F000表示未绑定） | ReleaseSyncServiceImpl:82 |
| 3 | 云端能通过MAC地址查到设备信息 | ReleaseSyncServiceImpl:111 |
| 4 | `isDiffRelease = true`（版本不一致） | ReleaseSyncServiceImpl:115 |

## 版本比较逻辑 (isDiffRelease)

### 数据源1：本地版本

读取本地文件 `/home/smyze/bar-deploy-data/.release`，配置项：

```yaml
# application-prod.yml
smyze:
  data-path:
    release-file: /home/smyze/bar-deploy-data/.release
```

文件内容为 JSON，对应 `ReleaseInfoBO`，参与比较的字段：

- `releaseId` (Long) — 版本ID
- `profile` (int) — 环境标识

读取代码：`DeviceUtils.getLocalRelease()` → 读取文件 → JSON反序列化

> 如果 `.release` 文件不存在，返回 null，直接判定为需要同步。

### 数据源2：云端版本

通过 HTTP 接口获取，调用链路：

1. `DeviceUtils.getMacCode()` 获取本机 MAC 地址（优先取 mock 值，否则读 enp1s0/wlo1 网卡）
2. `DeviceAdapter.queryDeviceInfo(null, mac, needDesc)` 调用云端接口
3. 返回 `DeviceInfoResDTO`，参与比较的字段：`device.releaseId` (Long)

> 如果云端查不到设备（device 为 null），判定为不同步。

### 比较规则

满足任一条件即判定为"需要同步"：

1. 云端 `device.releaseId` ≠ 本地 `.release` 中的 `releaseId`
2. 当前 Spring Profile (`spring.profiles.active`) ≠ 本地 `.release` 中的 `profile`

## 同步执行步骤

判定需要同步后，调用 `processSync()` 执行以下步骤：

### Step 1: 查询版本详情

调用云端接口 `GET /v1/admin-api/release/{releaseId}/info`，返回 `ReleaseInfoResBO`。

**中断条件**：如果 `shellGit` 为空 或 `imageList` 为空，直接跳过不同步。

### Step 2: 拉取 Docker 镜像

遍历 `imageList`，逐个执行 `docker pull`，完成后校验本地镜像数量是否与列表一致。

### Step 3: Git Clone 启动脚本

```yaml
# application-prod.yml
smyze:
  start-shell-git:
    repo-remote-url: https://codeup.aliyun.com/.../tools.git   # Git仓库地址
    repo-local-dir: /home/smyze/bar-deploy-data/tools           # 本地路径前缀
    repo-local-image-file: .image_versions                       # 镜像版本文件名
    username: xxx                                                 # Git只读用户名
    password: xxx                                                 # Git只读密码
```

执行命令：
```bash
git clone --branch {tag} --single-branch --depth 1 {url} /home/smyze/bar-deploy-data/tools-{releaseCode}
```

目标目录命名规则：`repo-local-dir` + `-` + `releaseCode`，例如 `/home/smyze/bar-deploy-data/tools-0.0.6`

### Step 4: 生效版本配置

1. 写入新的 `.release` 文件（更新本地版本记录）
2. 写入镜像版本到 `/home/smyze/bar-deploy-data/tools-{releaseCode}/.image_versions`
3. 更新 `/home/smyze/.image_env` 中的 `TOOLS_PATH` 指向新目录

> 如果此步骤失败，会自动回滚 `.release` 文件和 `.image_env` 到原始状态。

### Step 5: 清理历史资源（异步执行）

- 删除超过 `remove-old-tools-before-time`（默认30天）的旧启动脚本文件夹
- 删除超过配置时间的旧 Docker 镜像

## 关键文件汇总

| 文件路径 | 用途 | 读写方 |
|----------|------|--------|
| `/home/smyze/bar-deploy-data/.release` | 本地版本记录（releaseId, releaseCode, profile, imageVersion） | 读：版本比较时读取；写：同步成功后更新 |
| `/home/smyze/.image_env` | 全局环境变量（TOOLS_PATH, PROFILES_ACTIVE 等） | 写：同步成功后更新 TOOLS_PATH |
| `/home/smyze/bar-deploy-data/tools-{releaseCode}/` | 启动脚本目录，从 Git 仓库 clone | 写：Git clone 创建 |
| `/home/smyze/bar-deploy-data/tools-{releaseCode}/.image_versions` | 镜像版本环境变量文件 | 写：同步成功后写入 |

## 排查不同步问题

查看设备日志，搜索以下关键字：

| 日志关键字 | 含义 |
|-----------|------|
| `releaseSync is disabled` | 同步开关未开启 |
| `releaseSync is not sync for F000` | 设备未绑定（主机名为F000） |
| `当前主机没有和云端进行绑定` | MAC地址在云端未找到对应设备 |
| `diff release:false` | 版本一致，无需同步 |
| `diff release:true` | 版本不一致，将触发同步 |
| `查询版本镜像详情为空` | 云端版本缺少 shellGit 或 imageList 配置 |
| `开始执行版本同步` | 已进入同步流程 |
| `同步版本失败` | 同步过程中发生异常（Docker拉取失败/Git clone失败等） |
| `执行拉取镜像失败` | Docker镜像拉取后数量校验不通过 |
| `执行同步启动脚本失败` | Git clone 命令执行失败 |
| `启动脚本不存在，执行失败` | Clone完成但目录不存在 |
| `启动脚本切换失败` | 写入版本配置失败，会自动回滚 |
