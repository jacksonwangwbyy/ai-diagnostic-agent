# 测试配置文件规范 v1

## 1. 目标

本规范用于定义自动化测试服务读取的测试配置文件格式。

服务职责：

- 解析测试配置文件
- 提供开始、暂停等控制接口
- 按配置顺序调用 `bar_middleware` 提供的硬件接口
- 在测试完成、失败或暂停后输出测试报告

本规范只描述测试编排，不直接描述硬件底层通信细节。

## 2. 设计原则

- 配置文件格式使用 `YAML`
- 配置文件只允许声明预定义动作，不允许直接写任意 HTTP URL
- 步骤只支持严格顺序执行，不支持并发、分支、条件跳转
- 机械臂移动只支持既定点位编码方式，不支持直接写坐标、姿态、轨迹
- 流程暂停后，当前运行立即结束，并输出已完成部分的测试报告
- 下次再次开始时，默认从头重新执行
- 步骤失败策略支持配置化，可按运行级、流程级、步骤级覆盖
- 支持全局默认超时/重试，也支持步骤级覆盖

## 3. 顶层结构

```yaml
version: 1

job:
  name: string

report:
  formats: [json, html]
  output_dir: string

runtime:
  pause_mode: stop_and_finalize_report
  default_timeout_ms: number
  default_retry_times: number
  failure_policy:
    action: stop_run

flows:
  - id: string
    name: string
    cycles: number
    enabled: true
    on_failure: string
    steps:
      - name: string
        action: string
        timeout_ms: number
        retry_times: number
        on_failure: string
        critical: boolean
        params: {}
```

## 4. 字段定义

### 4.1 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `version` | number | 是 | 配置版本，v1 固定为 `1` |
| `job` | object | 是 | 任务基础信息 |
| `report` | object | 是 | 报告输出配置 |
| `runtime` | object | 是 | 运行时默认策略 |
| `flows` | array | 是 | 流程定义列表 |

### 4.2 `job`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `job.name` | string | 是 | 任务名称，用于日志、报告展示 |

### 4.3 `report`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `report.formats` | array[string] | 是 | 报告格式，v1 支持 `json`、`html` |
| `report.output_dir` | string | 是 | 报告输出目录 |

约束：

- `report.formats` 至少包含一种格式
- `report.formats` 中的值只能是 `json` 或 `html`

### 4.4 `runtime`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `runtime.pause_mode` | string | 是 | 暂停策略，v1 固定为 `stop_and_finalize_report` |
| `runtime.default_timeout_ms` | number | 是 | 默认步骤超时时间，单位毫秒 |
| `runtime.default_retry_times` | number | 是 | 默认步骤重试次数，最小值 `0` |
| `runtime.failure_policy` | object | 是 | 运行级默认失败策略 |

`runtime.failure_policy` 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `runtime.failure_policy.action` | string | 是 | 默认失败动作 |

允许值：

- `stop_run`：终止整个运行并输出部分报告
- `skip_step`：跳过失败步骤，继续当前 flow 后续步骤
- `skip_flow`：跳过当前 flow 本轮剩余步骤，进入下一个 flow

### 4.5 `flows`

`flows` 为流程列表。服务按数组顺序依次执行每个启用的流程。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `flows[].id` | string | 是 | 流程唯一标识 |
| `flows[].name` | string | 是 | 流程名称 |
| `flows[].cycles` | number | 是 | 当前流程循环次数，最小值 `1` |
| `flows[].enabled` | bool | 是 | 是否启用该流程 |
| `flows[].on_failure` | string | 否 | flow 级失败策略，未配置时继承 `runtime.failure_policy.action` |
| `flows[].steps` | array | 是 | 步骤列表 |

约束：

- `flows[].id` 在同一个配置文件中必须唯一
- `flows[].steps` 不能为空

### 4.6 `steps`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `steps[].name` | string | 否 | 步骤显示名称，用于日志和报告 |
| `steps[].action` | string | 是 | 预定义动作名 |
| `steps[].timeout_ms` | number | 否 | 当前步骤超时时间，未配置时使用 `runtime.default_timeout_ms` |
| `steps[].retry_times` | number | 否 | 当前步骤重试次数，未配置时使用 `runtime.default_retry_times` |
| `steps[].on_failure` | string | 否 | step 级失败策略，未配置时继承 `flows[].on_failure` 或运行级默认策略 |
| `steps[].critical` | bool | 否 | 是否关键步骤。为 `true` 时，失败后强制按 `stop_run` 处理 |
| `steps[].params` | object | 否 | 动作参数 |

约束：

- `steps[].timeout_ms` 必须大于 `0`
- `steps[].retry_times` 最小值为 `0`
- `steps[].critical` 默认值为 `false`
- `steps[].params` 只能包含当前动作允许的字段

## 5. 动作清单

v1 只支持以下预定义动作。

### 5.1 机械臂动作

#### `robot.initialize`

说明：

- 初始化机械臂

参数：

- 无

#### `robot.finalize`

说明：

- 结束机械臂会话或释放连接

参数：

- 无

#### `robot.stop`

说明：

- 停止机械臂当前动作

参数：

- 无

#### `robot.move_to_pose`

说明：

- 控制机械臂移动到既定点位编码
- 测试程序只负责读取 `target_pose` 并传递给 `bar_middleware`
- 不允许在配置文件中直接写坐标、姿态或轨迹

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.target_pose` | string | 是 | 已在 `bar_middleware` 中配置好的点位编码 |

约束：

- `target_pose` 必须是部署环境中可识别的点位编码
- 例如：`cup_lid_pre`、`deliver_0`、`idle_0`

#### `robot.check_gripper`

说明：

- 检查机械臂夹爪是否持有物体
- 通过读取夹爪 DI 信号判断当前状态
- 将实际状态与 `expected` 参数对比，不匹配时视为步骤失败
- 建议在关键操作前后使用，配合 `critical: true` 确保安全

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.expected` | string | 是 | 期望状态，允许值：`empty`（期望手爪为空）、`holding`（期望手爪持有物体） |

典型用法：

- 接杯前：`expected: empty`（确认手上没有东西）
- 接杯后：`expected: holding`（确认已拿到杯子）
- 扣盖前：`expected: holding`（确认杯子还在）
- 扣盖后：`expected: holding`（确认杯子没掉）
- 丢杯前：`expected: holding`（确认杯子还在）
- 丢杯后：`expected: empty`（确认杯子已放下）

### 5.2 落杯器动作

#### `cup.dispense`

说明：

- 执行落杯

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.cup_type` | string | 是 | 杯型，允许值：`cold`、`hot`、`icecream` |

#### `cup.check`

说明：

- 检查对应杯型状态

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.cup_type` | string | 是 | 杯型，允许值：`cold`、`hot`、`icecream` |

### 5.3 扣盖机动作

#### `lid.pre_check`

说明：

- 扣盖前状态检查

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.cup_type` | string | 是 | 杯型，允许值：`cold`、`hot` |

#### `lid.dispense`

说明：

- 执行扣盖

参数：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `params.cup_type` | string | 是 | 杯型，允许值：`cold`、`hot` |

### 5.4 标签机动作

#### `printer.print_test`

说明：

- 触发打印机测试打印
- v1 只支持测试打印，不要求传业务标签内容

参数：

- 无

## 6. 参数编码规范

### 6.1 杯型编码

统一使用字符串，不使用数字枚举。

| 配置值 | 含义 |
|---|---|
| `cold` | 冷杯 |
| `hot` | 热杯 |
| `icecream` | 冰淇淋杯 |

### 6.2 机械臂点位编码

统一使用 `bar_middleware` 已配置好的点位编码名称。

示例：

- `cup_lid_pre`
- `deliver_0`
- `idle_0`

说明：

- 配置文件中只保留点位名，不保留笛卡尔坐标
- 点位实际含义和路径由 `bar_middleware` 当前部署环境决定

### 6.3 夹爪期望状态编码

| 配置值 | 含义 |
|---|---|
| `empty` | 期望夹爪为空（无物体） |
| `holding` | 期望夹爪持有物体 |

## 7. 执行语义

### 7.1 流程执行顺序

- 先按 `flows` 数组顺序执行
- 每个 `flow` 内按 `steps` 数组顺序执行
- `flow.cycles = N` 表示该流程完整执行 `N` 次

### 7.2 重试策略

- 每个步骤默认使用 `runtime.default_retry_times`
- 如果步骤配置了 `retry_times`，则覆盖默认值
- 一次执行失败后，若剩余重试次数大于 `0`，则重新执行该步骤
- 所有重试仍失败，则本次运行结束并生成部分报告

### 7.3 超时策略

- 每个步骤默认使用 `runtime.default_timeout_ms`
- 如果步骤配置了 `timeout_ms`，则覆盖默认值
- 步骤超时视为步骤失败

### 7.4 暂停策略

- 当外部调用暂停时，服务停止继续调度后续步骤
- 当前运行状态标记为已暂停结束
- 立即生成截至暂停时已完成部分的测试报告
- 下次重新开始时，从头开始执行，不做断点续跑

### 7.5 失败策略

失败策略支持三层覆盖：

- 运行级：`runtime.failure_policy.action`
- flow 级：`flows[].on_failure`
- step 级：`steps[].on_failure`

优先级：

- `steps[].critical = true` 时，失败后始终按 `stop_run` 处理
- 否则按 `steps[].on_failure`
- 若 step 未配置，则按 `flows[].on_failure`
- 若 flow 未配置，则按 `runtime.failure_policy.action`

允许动作：

- `stop_run`
  - 终止整个运行
  - 不再执行后续任何 flow
  - 输出已完成部分的测试报告
- `skip_step`
  - 当前步骤标记为失败
  - 继续执行当前 flow 的下一个步骤
  - 报告中需记录该步骤失败及跳过事实
- `skip_flow`
  - 当前步骤标记为失败
  - 当前 flow 本轮剩余步骤不再执行
  - 直接进入下一个 flow
  - 报告中需记录 flow 被提前终止

推荐实现约束：

- 对 `robot.initialize`、`robot.finalize`、`robot.stop` 建议默认视为关键步骤
- 若步骤已重试耗尽，才触发失败策略动作
- 无论采用哪种失败策略，报告都必须记录：
  - 失败步骤
  - 失败原因
  - 已执行重试次数
  - 最终采用的失败策略

## 8. 校验规则

服务在接收配置文件后，至少应执行以下校验：

- `version` 是否受支持
- `flows` 是否为空
- `flows[].id` 是否重复
- `cycles` 是否大于等于 `1`
- `action` 是否属于预定义动作
- `runtime.failure_policy.action` 是否为允许值
- `flows[].on_failure` 是否为允许值
- `steps[].on_failure` 是否为允许值
- `params` 是否符合动作要求
- `cup_type` 是否为允许值
- `target_pose` 是否非空
- `expected` 是否为允许值（`empty` 或 `holding`）

可选增强校验：

- 启动时从 `bar_middleware` 加载当前可用点位编码，校验 `target_pose` 是否存在

## 9. 示例

```yaml
version: 1

job:
  name: 热杯扣盖贴标稳定性测试

report:
  formats: [json, html]
  output_dir: /data/test-runner/reports

runtime:
  pause_mode: stop_and_finalize_report
  default_timeout_ms: 10000
  default_retry_times: 0
  failure_policy:
    action: stop_run

flows:
  - id: hot_flow
    name: 热杯流程
    cycles: 1000
    enabled: true
    on_failure: skip_flow
    steps:
      - name: 机械臂初始化
        action: robot.initialize
        critical: true

      - name: 热杯落杯
        action: cup.dispense
        timeout_ms: 8000
        retry_times: 1
        on_failure: stop_run
        params:
          cup_type: hot

      - name: 机械臂移动到扣盖前点位
        action: robot.move_to_pose
        params:
          target_pose: cup_lid_pre

      - name: 扣盖前检查
        action: lid.pre_check
        params:
          cup_type: hot

      - name: 扣盖
        action: lid.dispense
        timeout_ms: 12000
        params:
          cup_type: hot

      - name: 机械臂移动到成品区
        action: robot.move_to_pose
        params:
          target_pose: deliver_0

      - name: 打印测试标签
        action: printer.print_test

      - name: 机械臂结束
        action: robot.finalize
        critical: true
```

## 10. 推荐实现

建议服务内部按以下顺序处理单步执行：

1. 根据步骤定义解析目标动作和参数
2. 应用当前步骤超时和重试配置
3. 调用 `bar_middleware`
4. 若成功，记录成功结果并进入下一步
5. 若失败且仍有重试次数，继续重试
6. 若重试耗尽，计算最终失败策略
7. 根据失败策略执行：
   - `stop_run`：终止运行并出报告
   - `skip_step`：记录失败并继续后续步骤
   - `skip_flow`：记录失败并切换到下一个 flow

推荐保留如下报告字段：

- `run_status`
- `flow_id`
- `cycle_index`
- `step_name`
- `action`
- `params`
- `attempt_count`
- `success`
- `error_message`
- `failure_action`
- `start_time`
- `end_time`
- `duration_ms`

## 11. v1 范围说明

本版本暂不支持以下能力：

- 动态条件分支
- 并发步骤
- 子流程嵌套
- 断点续跑
- 直接写 HTTP URL
- 直接写机械臂坐标、姿态、轨迹
- `printer.print_label` 业务参数打印

上述能力如后续确有需求，可在 `v2` 再扩展。
