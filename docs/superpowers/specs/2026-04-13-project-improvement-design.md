# AI Diagnostic Agent 项目完善设计方案

> 日期: 2026-04-13
> 状态: 已确认

## 概述

将 12 项待完成内容分为 4 个迭代批次，按优先级逐步推进。每个迭代先设计、再实现、后审查。

---

## 迭代 1：基础质量保障（高优先级）

**目标**：确保代码质量和数据完整性

### 1.1 清理 log_reader.py 重复代码

- **问题**：`_read_local()` 和 `_read_ssh()` 函数各定义了两次（疑似合并残留）
- **方案**：删除重复的函数定义，保留正确版本
- **验证**：确保现有功能不受影响

### 1.2 填充故障案例库

- **目标**：基于 14 份设备手册内容，AI 生成 20-30 个模拟故障案例
- **格式**：Markdown 文件，每个案例包含：
  - 故障现象描述
  - 涉及设备/模块
  - 故障原因分析
  - 解决方案/维修步骤
  - 关键日志片段示例
- **存放**：`knowledge-base/fault-cases/` 目录
- **分类**：按设备模块分组（中间件、机器人臂、物料监控、视频传输等）
- **后续**：重新构建知识库，将故障案例纳入 RAG 检索

### 1.3 构建测试套件

- **框架**：pytest + pytest-asyncio
- **策略**：单元测试（Mock 外部依赖）+ 集成测试（FastAPI TestClient）
- **覆盖范围**：
  - `src/llm/client.py` — 多模型切换、降级逻辑、流式输出
  - `src/rag/` — 文档加载、文本分割、向量存储、RAG 链
  - `src/tools/` — 4 个工具的参数验证、正常/异常场景
  - `src/api/` — 7 个 API 端点的请求/响应验证
  - `src/utils/session_store.py` — Redis 和内存后端
- **Mock 策略**：
  - LLM API → mock 响应
  - Redis → 内存后端回退
  - SSH → mock paramiko
  - bar_middleware API → mock httpx/requests
  - ChromaDB → 临时内存实例

## 迭代 2：RAG 优化 & 评估（中优先级 - 检索质量）

**目标**：提升诊断准确率

### 2.1 检索质量优化

- **Reranking**：引入 CrossEncoder 对初次检索结果重排序
- **混合检索**：语义检索 + BM25 关键词检索，结果融合
- **查询改写**：利用 LLM 将用户口语化描述转为结构化查询

### 2.2 RAG 评估体系

- **评估数据集**：构建 Q&A 对（问题 + 预期答案 + 预期来源文档）
- **指标**：
  - 检索准确率（Recall@K, Precision@K, MRR）
  - 回答质量（与参考答案的语义相似度）
  - 来源归因准确率
- **自动化**：脚本化评估流程，可重复运行

### 2.3 新增诊断工具

- **设备重启工具**：通过 API/SSH 发送重启命令
- **固件版本检查工具**：查询设备固件版本，与最新版本对比

## 迭代 3：多 Agent 协作系统（中优先级 - 架构升级）

**目标**：从单 Agent 升级为完整多 Agent 编排系统

### 3.1 Agent 编排引擎

- **架构**：基于 LangGraph 构建 Supervisor Agent
- **职责**：
  - 接收用户请求，分析任务类型
  - 分发任务到对应专业 Agent
  - 汇总各 Agent 结果，生成最终响应
- **工作流**：StateGraph 定义 Agent 间的转换逻辑

### 3.2 维修建议 Agent

- **职责**：基于诊断结果生成维修方案
- **输出**：维修步骤、所需备件清单、预估时间、注意事项
- **工具**：知识库搜索（维修手册）、备件查询

### 3.3 设备监控 Agent

- **职责**：持续监控设备状态
- **能力**：异常检测、趋势分析、预警通知
- **工具**：设备状态查询、日志监控、历史数据分析

### 3.4 Agent 间通信

- **共享状态**：通过 LangGraph State 传递上下文
- **结果传递**：诊断 Agent → 维修 Agent 的结果流转
- **协作流程**：诊断 → 确认 → 维修建议 → 监控跟踪

## 迭代 4：前端增强 & 文档完善（低优先级）

**目标**：提升用户体验和项目可维护性

### 4.1 前端功能增强

- **技术栈**：在现有 React + Vite + TypeScript 基础上增量开发
- **新增功能**：
  - 会话历史管理 UI（列表、切换、删除）
  - 模型/供应商选择面板
  - 诊断报告导出（PDF/JSON）
  - 设置页面（API 配置、主题等）
  - 错误恢复 UI（重试、断线重连）

### 4.2 安全加固

- SSH 命令注入：引入白名单校验替代正则
- 输入验证：对所有 API 输入增加 Pydantic 严格校验
- API 限流：添加请求频率限制

### 4.3 文档补充

- API 集成指南：bar_middleware 接口说明
- 故障排查手册：常见部署/运行问题
- 部署最佳实践：Docker 生产配置、环境变量管理
- 性能调优：向量检索优化、LLM 调用优化

| 决策 | 选择 | 原因 |

| 故障案例数据 | AI 生成模拟数据 | 快速填充，覆盖常见场景 |

| 多 Agent 架构 | 完整编排系统 | Supervisor 模式，最大灵活性 |
| 前端改进 | 增量增强 | 保留现有代码，降低风险 |
| 执行方式 | 分批迭代 | 快速交付，及时调整 |
